# 跨服场景设计预留

跨服复用 worldServer 管理和 cell 执行，不新增另一种进程。Space 对应现有 Scene 空间语义，临时活动关联 Instance；术语与代码见[体系对照](./bigworld-apollo-mapping.md)。玩家原 Base、区服与数据库归属不变。

## 注册与独立部署

Base/World 向 loginServer 托管的服务目录发布逻辑身份、地址、代次、兼容版本和就绪；cell 向所属 worldServer 注册负载与执行能力。World 决定 Space/Cell 分配并发布位置投影，目录不另行裁决分区。

machined 只监督本机进程。独立 World/cell 不要求同机 machined，也不获取各小服数据库凭证。跨服池按配置选择准入范围，仍使用相同管理与执行职责。

## 准入契约

| 数据 | 作用 |
|---|---|
| 玩家 ID、原区服、Base 身份及归属版本 | 保留资料所有者，来源由服务端验证。 |
| 源/目标 World、Space、Cell、执行进程、可选 Instance | 区分管理域、运行空间、分区与承载地址。 |
| 进程代次、实体模拟代次、拓扑版本 | 拒绝旧执行进程和旧分配；与 Base 写入代次分开。 |
| gateway/session、会话与路由版本 | 保持连接并更新模拟出口。 |
| 迁移 ID、有期限准入与兼容版本 | 限定目标、成员、人数和交接，拒绝重放。 |
| 玩法基础快照、必要运行状态与状态版本 | 目标仅接收玩法所需资料，不搬完整档案。 |
| 稳定结算 ID、返回位置 | 幂等业务结果与原服安全返回。 |

这是目标契约，现有 WorldAssignment/wire 尚未包含全部字段。Base 地址由服务目录缓存解析，不把 IP 或数据库位置当玩家归属；home_zone_id 不直接等于业务区服。

## 权威交接

1. 原 Base 校验准入，World 选目标执行进程并保留返回位置。
2. 源 cell 在模拟边界冻结，排平或记录在途操作，导出必要运行状态；原 Base 继续拥有长期资料。
3. 目标 cell 校验准入、Base 关联、状态与代次，恢复为未激活状态。
4. World 管理权威按预期源和模拟代次条件提交；跨 World 由协调方取得唯一、可恢复的提交决定。目标凭据激活，目录更新投影，gateway 刷新路由。
5. 源 cell 删除旧实体与临时资源，确认完成；迟到源输入、结算与写入被代次校验隔离。

准备不等于激活。提交前取消必须确认未提交，结果不明查询持久记录，禁止双端解冻。完整 Instance 连续迁移还包括成员、怪物、目标、时钟、随机状态及必要脚本状态。

## 与无缝迁移的关系

跨服进入另一 Space 是显式换空间；未来同一 Space 跨 Cell 只是模拟归属变化，Space ID、坐标和实体 ID 保持，血量、冷却、计时与脚本状态连续，AOI 不发生完整离场重置。现有 SceneTransfer 离场后重建 Avatar，不能作为该路径的实现。

当前默认单执行进程、每 Space 单 Cell，不实现实际空间切分、Ghost 复制或跨边界战斗。接口预留同 Space 多 Cell、邻接、拓扑版本和权威交接，不以另一套架构命名表达。

## 结算与故障

cell 以稳定玩法/结算 ID 和模拟代次向各玩家原 Base 提交奖励、消耗与任务结果。Base 校验，再由 database 原子持久化资料变更及去重凭据。传输 ACK 不等于持久成功；结果不明查询或重试同一事务，不能换 ID 重记。

多 Base 分别确认，不宣称跨 Base 原子提交。部分成功、补偿、Base 暂不可达和结算未确认必须有恢复记录，不能提前销毁唯一凭据。离场返回原区服；原 Space 不可用则选安全空间。Base 升级只更新 Base 关联与代次，不改变原服和存储归属。

## 启用前验收

- 两区服、两 Base 同场，Base 和存储归属稳定；普通与临时 Space 均可寻址。
- cell 正确注册到 World，无 machined 独立部署可用；失效与重注册拒绝旧代次。
- 准入、版本、容量、源冻结、准备、提交不明、重启及源清理都有真实故障覆盖。
- 多 Base 持久结算幂等，部分成功及安全返回可恢复。
- gateway 后端换路由、会话恢复与客户端 TCP 分别验收；未来无缝能力另行实施。
