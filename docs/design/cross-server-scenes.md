# 跨服场景设计预留

跨服是 World 的正式扩展要求，当前预留设计，暂不启用跨服部署。普通场景与跨服场景均使用既有 `World`、`Scene`、`Instance`，不增加进程类型，不实现无缝地图。

## 区服与运行位置

区服是玩家的业务归属，World 是承载模拟的进程，两者不能使用同一个 ID。一场跨服活动可接纳多个区服的玩家，由一个选定的 World 承载；同一 World 也可承载普通场景。以后可按容量和故障隔离需要配置跨服专用的 World 池，角色和程序仍为 `world-app`。

跨服 Scene 不要求一定临时销毁；需要小队创建、刷完销毁的跨服副本时，在 Scene 上关联既有 Instance，并遵循同一八态生命周期。不能把所有跨服玩法都约束成临时副本。

路由与迁移接口需保留以下语义；此表是目标接口要求，不表示当前 wire 已包含这些字段。

| 数据 | 作用 |
|---|---|
| 玩家唯一 ID、原区服 ID | 确认身份和业务归属；跨服不改原区服，不按目标 World 重新创建账号 |
| World ID、Scene ID、可选 Instance ID | 当前运行位置；Scene/Instance 的进程内编号须与 World 身份组合使用 |
| World 进程代次、玩家权威代次 | 拒绝进程重启前、迁移前的旧输入和旧写入；World ID 本身不能证明同一次进程运行 |
| 会话 ID、Gateway ID、路由版本 | 保留登录关系并更新转发；跨服不强制更换 Gateway |
| 迁移 ID、目标准入凭证与期限 | 关联同一次交接、去重和限定目标；服务端签发，不采信客户端声明的成员/落点 |
| 结算 ID、返回位置 | 奖励去重与退出恢复；返回位置包括原区服、World/Scene，以及安全回退位置 |

ID 的生成和编码沿用现有身份体系，在契约接线时扩展；不得把旧的 `home_zone_id` 字段直接当成已经实现的业务区服归属。

## 职责与分配

- Login 托管的在线目录保存业务归属与当前运行位置，负责落点选择和权威交接编排。目录的持久化与故障恢复必须在跨服启用前完成。
- Gateway 保持客户端连接，按当前路由转发；跨服只改变路由，不要求玩家重新登录。
- World 校验准入、持有玩家当前唯一权威对象及玩家资料写权，运行 Scene/Instance。
- 分配根据玩法配置的可参与区服、队伍成员、人数、版本兼容和 World 容量决定。客户端只能请求玩法，不能指定任意跨服目标。

普通玩法缺省只接纳所属区服；跨服玩法显式配置允许的区服集合、跨服分组及人数上限。没有启用跨服配置时维持普通玩法行为。分配必须避免重复创建同一小队请求，并在所选 World 排空、过载或失联时取消预留或重新选择。

## 权威交接

1. 验证成员资格与目标容量，记录迁移 ID、源/目标位置、返回位置和预期权威代次。
2. 源 World 在模拟边界冻结玩家，排平已确认的持久写入并导出状态。冻结后拒绝新的模拟输入和业务写入。
3. 目标 World 校验身份、版本、准入凭证和迁移 ID，恢复为待接管状态。此时只准备资源，不运行第二个权威对象。
4. 在线目录以预期源位置和权威代次进行条件提交，确认目标与新代次；目标取得提交凭据后才开始运行。Gateway 刷新路由，源端清除旧实体和写权。
5. 双方记录完成状态并释放快照/预留；重复请求返回同一次交接结果。

目标确认“已准备”不等于已经激活。超时且提交结果不明时先查询目录和迁移记录，不能直接让源端解冻。只有证明权威提交未发生，才允许取消目标预留并恢复源端；提交后以目标权威恢复，不双端回滚。输入携带会话与权威代次，迟到、重复和过期输入按规则拒绝。

进程内 SceneTransfer、同区服跨 World、跨区服场景准入分别验收：跨 World 是运行位置交接，跨服还必须满足区服策略、身份与结算规则。

## 结算、返回与故障

跨服期间玩家仍属于原区服，当前权威 World 持有唯一可写资料。原区服的异步奖励或管理写入必须转发至当前权威，或排队等待交接完成；不能同时修改两份档案。副本奖励沿用既有奖励/持久化接口，使用包含玩法唯一标识的结算 ID 去重，持久确认后才能向客户端宣布结算完成。

副本完成、主动离开、队伍解散或活动到期时，先完成结算，再通过同一交接协议返回。原 World 不可用时返回原区服中经重新分配的安全场景，不要求原临时 Scene 仍然存在。返回失败时保留可恢复状态、结算结果和返回任务，禁止清空资料后直接删除玩家。

掉线先按会话保活策略处理；重连依据在线目录恢复到当前跨服位置。目标崩溃、目录重启、结算重试与强制排空须通过持久迁移记录确定唯一权威。活动状态尚不可恢复时按活动失败处理，仍保留已确认奖励及返回信息；监督重启不等于跨服对局恢复。

## 启用前验收

- 至少两个业务区服的玩家进入同一 Scene/Instance，身份不冲突且原区服归属不变。
- 普通玩法拒绝未授权跨服；跨服准入拒绝伪造成员、过期凭证、人数超限及不兼容版本。
- 同区服与跨区服交接均保持单权威，覆盖每步超时、重复投递、路由延迟和两端重启。
- 结算重复执行不重复发奖，断线重连免重新登录，活动结束能够返回；原 World 不可用有安全回退。
- 一个 World 多场景隔离、多个 World 分配与排空有效；跨服 Scene 不以支持无缝地图或 TCP 连接交接作为前提。
