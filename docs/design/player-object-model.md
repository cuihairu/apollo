
# 玩家对象模型

Apollo 的目标模型在一场对局中只保留一个玩家权威运行对象。目标概念见[概念与命名](./concept-glossary.md)；`Player` 表示玩家身份，`Entity` 表示运行时对象，`Avatar` 是玩家参与对局时的实体表示。

## 所有权

- 登录前，账号由 `Login` 认证；登录凭证不承载玩家游戏对象。
- 玩家进入副本后，World 创建/恢复一个玩家实体，并成为该对象的唯一权威持有者。
- 玩家断线时，World 可按游戏规则短暂保留该实体等待重连；是否保留、保留多久由会话策略决定。
- 对局结束后，提交结算/持久化需要的数据，再销毁该对局中的玩家实体。

不把一个玩家拆成常驻 Base 对象和场景 Cell 对象。也不因断线、换服或 Gateway 更换而额外创建第二个权威玩家对象。

## 跨服迁移

玩家需要加入另一个 World 时，迁移的是同一个逻辑对象的权威归属：

```text
源 World：冻结并导出状态
目标 World：恢复并确认接管
路由目录/Gateway：切换到目标端
源 World：删除旧对象
```

在目标端确认前，源端仍是权威；确认后，目标端成为唯一权威。状态快照在迁移期间可能短暂复制，但同一玩家不能同时在两端接受输入、推进模拟或提交权威写入。失败时回滚到唯一源端，或报告迁移失败并保留可恢复状态。

## 与其他概念的边界

- `Session` 描述客户端连接对应的会话，不是玩家对象。
- `Gateway` 持有网络连接，不拥有玩家模拟权威。
- `Instance` 是对局及其临时状态；World 是承载它的进程。
- `Scene` 是 World 内部的权威模拟单元，拥有实体、AOI、玩家进出和 tick；Instance 管理关联场景的玩法生命周期。
- `BaseApp`、`CellApp`、Proxy/ghost 等属于外部引擎模型，不作为 Apollo 的目标对象分层。

## 当前实现

仓库中的 `PlayerAnchor`、`Avatar`、`Scene` 和 `Instance` 是既有代码组件。它们不意味着目标模型保留双玩家对象或 Base/Cell 进程拆分。当前原型尚未完成 World 间的对象状态迁移与端到端路由切换。
