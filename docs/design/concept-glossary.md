# Apollo 概念与命名

本页定义 Apollo 的唯一目标术语。进程职责为 `Login`、`Gateway`、`World`；玩法副本使用既有类型 `Instance`。实现形式与职责的对应见[服务器应用](../apps/index.md)。

| 名称 | 职责与边界 |
|---|---|
| `Login` | 验证账号并签发登录凭证，托管在线目录、落点与迁移编排。 |
| `Gateway` | 持有客户端连接、关联会话，并根据在线位置路由消息。 |
| `World` | 游戏逻辑进程；管理场景与多个独立 Instance，推进权威模拟，并托管玩家资料与持久化。可执行程序为 `world-app`，入口类型为 `WorldApp`。 |
| `Scene` | World 内部的模拟单元，拥有实体、AOI、玩家进出和 tick；不是进程名。 |
| `Instance` | 几名玩家组队创建的临时玩法副本。进入后完成刷怪等目标，结算并释放玩家、场景和临时资源，随后销毁。 |
| `Player` | 长期玩家身份。持久资料与对局中的运行实体职责分开。 |
| `Avatar` / `Entity` | 参与场景模拟的运行实体；玩家在对局中仅有一个可接受输入和写入权威状态的实体。 |
| `AOI` | Scene 内的实体可见性管理。 |
| `Persistence` | 保存跨副本数据和结算结果的模块能力。 |

## 副本创建与销毁

目标流程为：小队发起 → 选择 World → 创建 Instance 与 Scene → 校验成员准入 → 进入与运行 → 完成刷怪目标 → 结算 → 玩家离开 → 销毁副本和临时场景。

已有 `Instance` 使用 `Create → Initialize → Waiting → Running → Finishing → Rewarding → Draining → Destroyed` 八态生命周期。继续复用此状态机；销毁前须处理结算幂等、在途请求和玩家退出。无人在场、超时、失败退出等异常也必须有明确的收尾路径。

## 权威与更新

World 预留承载跨服场景：区服是玩家业务归属，World 是运行位置。跨服不改变原区服，也不创建第二个可运行的权威对象。普通和跨服玩法使用同一套 Scene / Instance，详见[跨服场景设计](./cross-server-scenes.md)。

跨 World 转移玩家时，源端冻结，目标端恢复并确认，Gateway 路由随后切换，最后清理源端。传输中的快照可短暂同时存在，但只有一个权威执行者。

协议更新修改契约并重新生成产物，需新旧协议兼容和发布验证；仅代码更新保持 wire 契约不变，可使用 Lua 模块替换或 C++ 进程滚动替换。现有运行时原语不等于生产发布全链路已经完成。

World 名称不承诺无缝大世界。Apollo 面向塔防、合作 PvE/PvP、竞技场和按小队创建、完成后销毁的副本。BigWorld/KBEngine 专有名称仅在外部引擎资料中使用。
