# Gateway 职责与更新边界

本文定形 Apollo 房间制架构中的 Gateway 职责。目标拓扑见[架构总览](../guide/architecture.md)；名称比较见[多人游戏服务器常见名称对照](../36-MMO_Frameworks_Comparative_Analysis.md)。

## Gateway 的职责

1. 接受客户端游戏连接并管理连接生命周期。
2. 验证登录凭证、关联登录会话并执行连接级限流。
3. 按在线路由转发客户端消息，并把 RoomServer 的响应发回对应客户端。
4. 在连接断开时上报会话状态，支持客户端使用新连接恢复会话。

Gateway 不拥有玩家对局对象，不运行房间模拟，也不代替登录认证或房间准入。一个 RoomServer 可承载多个房间；Gateway 依据玩家当前路由转发到相应 RoomServer。

## 多 Gateway

多个 Gateway 可以分担新连接和网络带宽。每条既有 TCP 连接仍由接受它的 Gateway 进程持有；RoomServer 路由变更只改变后续消息目的地，不会移动 socket。Gateway 实例需有唯一实例身份，避免目录和服务间链路把多个副本误认为同一端点。

## 更新方式与承诺

| 目标 | 所需机制 | 结论 |
|---|---|---|
| 新连接持续接入 | 多 Gateway 实例；旧实例停止接受新连接 | 可实现服务端入口滚动更新。 |
| 既有连接不掉线 | 旧 Gateway 在排空期间继续持有连接，或实现跨进程连接交接 | 单靠多实例和负载均衡不够。 |
| 客户端不重新登录 | 客户端重连 + 可验证的会话恢复流程 | 允许连接重建，不能称为 TCP 无缝迁移。 |
| 活动房间不中断 | Room 状态迁移、目标版本兼容、权威接管、路由切换和回滚 | Gateway 不提供此能力；需要 RoomServer 迁移方案。 |

排空更新的一般步骤是：新 Gateway 开始接收新连接；旧 Gateway 停止接受新连接但继续服务既有连接；旧连接自然离开或达到排空期限后，旧进程退出。达到期限仍在线的客户端需要重连或连接迁移策略。

## 当前实现状态

仓库有 `gateway-app` 原型，但它尚未形成经验证的多实例生产拓扑或跨进程 TCP 连接交接。在线路由切换与 RoomServer 权威迁移也尚未形成端到端验收。部署副本数、进程启动成功或链路可靠传输都不能单独作为“客户端无感热更新”的证据。
