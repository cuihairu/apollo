
# Gateway 职责与更新边界

本文定形 Apollo 副本制架构中的 Gateway 职责。目标拓扑见[架构总览](../guide/architecture.md)；名称比较见[多人游戏服务器常见名称对照](../36-MMO_Frameworks_Comparative_Analysis.md)。

## Gateway 的职责

1. 接受客户端游戏连接并管理连接生命周期。
2. 验证登录凭证、关联登录会话并执行连接级限流。
3. 按在线路由转发客户端消息，并把 World 的响应发回对应客户端。
4. 在连接断开时上报会话状态，支持客户端使用新连接恢复会话。

Gateway 不拥有玩家对局对象，不运行副本模拟，也不代替登录认证或副本准入。一个 World 可承载多个副本；Gateway 依据玩家当前路由转发到相应 World。

## 多 Gateway

多个 Gateway 可以分担新连接和网络带宽。每条既有 TCP 连接仍由接受它的 Gateway 进程持有；World 路由变更只改变后续消息目的地，不会移动 socket。Gateway 实例需有唯一实例身份，避免目录和服务间链路把多个副本误认为同一端点。

## 更新方式与承诺

| 目标 | 所需机制 | 结论 |
|---|---|---|
| 新连接持续接入 | 多 Gateway 实例；旧实例停止接受新连接 | 可实现服务端入口滚动更新。 |
| 既有连接不掉线 | 旧 Gateway 在排空期间继续持有连接，或实现跨进程连接交接 | 单靠多实例和负载均衡不够。 |
| 客户端不重新登录 | 客户端重连 + 可验证的会话恢复流程 | 允许连接重建，不能称为 TCP 无缝迁移。 |
| 活动副本不中断 | Instance 状态迁移、目标版本兼容、权威接管、路由切换和回滚 | Gateway 不提供此能力；需要 World 迁移方案。 |

排空更新的一般步骤是：新 Gateway 开始接收新连接；旧 Gateway 停止接受新连接但继续服务既有连接；旧连接自然离开或达到排空期限后，旧进程退出。达到期限仍在线的客户端需要重连或连接迁移策略。

## 两种更新方案

Apollo 区分协议/契约更新与仅代码更新。两者都可以采用多实例滚动发布，但是否能让进行中的对局和既有连接无感，取决于各自的兼容和排空机制。

| 方案 | 更新内容 | 发布步骤 | 影响与边界 |
|---|---|---|---|
| 协议更新 | 修改 `sdks/contract/` 的 XML/XSD，并重新生成协议产物；通常也需要更新服务端和客户端 SDK | 先发布能兼容新旧契约的服务端，再发布客户端/协议产物；在兼容窗口结束后移除旧版本支持 | 已实现 `APOLLO_ROUTE_COMPAT` 握手兼容窗口，并用 `drill_proto_update.sh` 验证开窗发布、关窗拒绝和回滚。窗口只放行契约版本，不提供旧报文自动解码；字段布局、默认值和业务语义仍需按代次逐项验证。破坏性变更不能靠加白名单解决。 |
| 仅代码更新 | 不改变契约、消息编号、字段类型或 wire 格式；可更新 Lua 玩法模块，C++ 变更采用二进制滚动替换 | Lua 模块可在目标 World 的 tick 边界提交、观察或回滚；C++ 进程先停止接收新副本，再排空或迁移现有副本后替换 | `fleetctl module` 已连接多个 World，执行灰度预备、提交、观察、推广与故障回滚；`drill_module_update.sh` 验证双 World 发布及回滚。C++ 通过 Gateway/World 排空控制面执行进程替换，期限到仍有连接或副本时明确强停。 |

两种方案都不能由“多 Gateway”自动保证 TCP 连接不断。Gateway 进程仍持有原 TCP socket；滚动期间旧实例可继续服务已有连接，新实例接入新连接。若要求旧连接跨进程延续，需要独立的连接交接实现；若允许重连但不重新登录，还需要会话恢复协议。

## 当前实现状态

现有控制面包含 Gateway 和 World 的 begin/status 排空、Lua 多 World 发布，以及链路契约版本兼容窗口。`GatewayDrainTests`、`WorldDrainTests` 和相应演练覆盖正常排空与期限强停。它们不证明多实例生产部署、客户端会话恢复或跨进程 socket 交接已完成。

`MigrationChainTests` 已验证 Login 编排两端 World 的冻结、导出、接权和目录改指；源对象仍保留冻结状态，不能称为完整的对象迁移和失败回退。

### 连续性验收口径

| 路径 | 可验证结果 | 尚未覆盖 |
|---|---|---|
| Lua 模块更新 | `UpdateContinuityTests` 验证运行中副本跨 prepare/commit 推进并完成结算销毁；真实客户端 socket 用例验证原连接和会话继续操作、新连接可接入 | 原型认证不代表生产账号服务；跨 Gateway 重连恢复、多实例负载入口和故障发布下的全链连续性仍需单独验收 |
| World C++ 替换 | 旧 World 排空后退出，同端口新 World 可重新接入；Gateway 出口有界保留未发送请求，重连后顺序投递 | 内部 TCP 会重建，旧 Instance 不跨进程保留；不能宣称副本连续或真实玩家会话已恢复 |
| 协议更新 | 版本兼容窗口开关和回滚已有进程演练 | 新旧业务报文的双版本解码、真实客户端升级和活动副本跨版本连续性 |

World 进程代次变更时，已经发送但未收到业务确认的请求属于结果不明，Gateway 不自动重放；否则可能重复执行已经生效的操作。尚未发送的消息留在有界队列中，连接恢复后按受理顺序发送；队列满时拒绝受理。跨进程幂等裁决与会话恢复仍是业务恢复流程的责任，链路可靠传输不能替代它们。
