## 执行摘要

1. **确定性在 apollo 是「半件」问题——先裁域，再定约束**：服务器权威模型下不存在 lockstep 的跨端浮点一致性问题（客户端不判定——attribute-sync §9 预测/表现校正，漂移容忍）；需要确定性的只有三个消费方——**回放复算**（反作弊对账/bug 复现）、**跨进程战斗卸载**（36 号 #16 实例可在别机跑）、**AI 重算**（重放中重导出决策）。三者的要求同构：**同 binary 同平台 = 同确定域**。跨编译器/跨 OS 不承诺（回放器用录制时同版本 binary）。
2. **四约束**：① 判定域唯一——判定全部在 owning 场景线程 tick 边界内，异步结果不进判定；② 浮点纪律——IEEE754 + 编译档锁（`-ffp-contract=off` 等），**不做定点**（定点是 lockstep 跨端手段，此处无对应收益）；③ 迭代序——模拟段不要求序（独立实体），结算段按 **target entity_id 全序**应用效果；④ 随机数——`(world_seed, tick, stream_id)` 子流派生（PCG32），无全局状态游标，任意 tick 独立可重放。
3. **回放 = 四元组 + hash 链**：`(binary_id, world_seed, 起始快照位点, 输入序列)`；重放器逐 tick 重模拟，每 tick 末对战斗事件流按规范序（entity_id）算滚动 hash 与线上对照——分歧点即 bug/作弊点。**两种形态分开**：观战/精彩回放 = 事件流重演（不重模拟，cheap）；复算回放 = 重模拟 + hash 对照（贵，按需开）。
4. **AI 是重算的不是录制的**：AI 决策走确定性子流——重放时同 seed 同 tick 重导出同样决策，录制面只含玩家上行 intent，体积可控。
5. **Lua 侧同纪律**：rng/clock 经注入（沙盒已裁 `os.time`/`math.random`，scripting-lua §4）；结算遍历禁 `pairs`（无序）；指令预算截断本身确定性（指令流确定 → 截断点确定）。
6. **前置**：C-34 三套 ECS 收敛（战斗系统单套化）——三套并存时「战斗管线」无单一宿主，本件约束无处落。

## 0. 为什么是「半件」：负空间与先例

- 三仓零 lockstep 实现（deep-dive §18：BW/KBE/skynet 负空间检索零命中）；「确定性浮点/确定性迭代序在大世界引擎中无先例约束——这正是『只留缝不做实现』的理由」（deep-dive §18 已知缺陷面原文）。本件即该缝的填充：**外部无先例可抄，逐约束自证**。
- BW/KBE 的战斗判定同为服务器权威 + 脚本（Python）随机用全局 random——不可重放（无子流纪律、无输入录制），两家的「回放」不存在。36 号 #16 标注「自创+借鉴」属实（deep-dive §16）。
- docs/25（已删）遗产两件可收：五段管线（Input → Validation → Execution → Settlement → Broadcast，§3.3）与「关键战斗持久化 + 回放数据记录」（§3.4）的方向——但浮点/迭代序/种子/录制格式零展开，本件新建。

## 1. 判定域：唯一写者与 tick 边界

- **判定 = 场景线程 tick 边界内的纯函数段**：输入 =（本 tick 前世界态, 玩家 intent 集, 确定性子流）；输出 =（新世界态, 战斗事件集）。attribute-sync §10 六阶段的 simulate 段即此；前四段（input/validate/execute/settle）确定性，**broadcast 段非确定**（下发顺序/trim/丢包不影响世界状态——事件集本身是输出，怎么发是 net 的事）。
- **异步不进判定**：战斗中需要的外部数据（目标属性、配置表）必须在 tick 开始前就绪；异步任务（DB/GM/跨服查询）回包走 scripting-lua §8 交接 + re-validate——回包落点是**未来某 tick 的输入**，不是本 tick 判定中间插一脚。
- **跨进程卸载的确定域**（36 号 #16）：战斗实例迁到独立进程/机器 = 同 binary 部署（构建产物统一 CI 出），确定域不变；实例与 owner 进程的交互 = 事件流 + intent 流（InterServerLink），两段各自确定性。

## 2. 浮点纪律

| 约束 | 口径 | 理由 |
|---|---|---|
| 表示 | IEEE754 binary32/64；关键裁决量（命中距离/数值比较）允许 float | 同 binary 同平台重放天然一致——确定性由「单一判定域」保证，不靠定点 |
| 编译档 | `-ffp-contract=off`（禁 FMA 融合）、`-fno-fast-math`（禁重结合/近似）、SSE2 基线（x86-64 默认，禁 x87 80bit 路径）、**禁 `-march=native`**（构建产物必须跨机器统一——native 产物在不同 CPU 上走不同向量路径） | FMA/快数浮点是同源码跨编译设置漂移的头号源；native 构建让「同 binary」前提破裂。工具链档进 CMake preset（代码批登记） |
| 不做定点/fixed64 | 判定不跨端，float 即确定 | 定点是 lockstep 手游为跨端一致/省带宽付出的开发成本（三角函数查表/精度管理），此处无对应收益——36 号 #18 缝口径的具体化 |
| 混算 | 判定路径禁 double↔float 隐式转换（编译警告级 lint） | 隐式截断点漂移是排查地狱 |
| Lua 侧 | Lua 5.5 number = double/int64（scripting-lua §2 版本锁定：5.5 主线随 vcpkg，当前 5.5.x——number 语义不变）；判定脚本**禁 math 三角/超越函数**（跨 libc 版本实现差异）——角度/距离工具由 C++ 侧定点角度 + 查表函数注入 `apollo.battle`；`string.format` 不进判定 | libc 的 sin/exp 不承诺位一致；C++ 查表是同 binary 数据 |

## 3. 迭代序：稳定序源

- **模拟段不要求序**：各实体模拟只读世界态、写自身（单写者纪律的自然推论）——遍历序不影响结果，容器可无序。
- **结算段按 target entity_id 全序**：一个动作结算多目标（AOE 命中顺序影响谁先死/触发链）时，效果收集为集合，**按 target entity_id 升序应用**——结算集小（一场 AOE 十百级），排序成本可忽略；entity_id 单调分配（id_pool）是全序保证。
- **容器纪律**：判定路径禁 unordered 容器的迭代序参与结算（同进程内插删后迭代序也会变）；广播/收集用无序容器可以，**回放 hash 用规范序**（§5）不用发送序。
- 与 §2 同源：迭代序问题只存在于「同 tick 内互写的多对象」——全序应用把任意迭代序归一为同一结果。

## 4. 随机数：子流派生

```
state = pcg32_init( splitmix64( world_seed, tick, stream_id ) )   // 每 (tick, stream) 独立子流
```

- **子流模型**：无全局 RNG 状态、无顺序敏感游标——任意 tick 任意流独立可重放（不用「按调用次数续流」，调用次序变化即漂移，且无法局部重放）。
- **stream_id 分域**：`combat_roll`（命中/暴击/抵抗）/ `drop`（掉落）/ `ai_decision`（AI 决策）/ `proc`（触发链）——各系统不共享子流，一个系统抽几次不影响别系统序列（跨系统耦合是隐性序依赖）。
- **world_seed**：建服随机生成一次、持久化（进服务器元数据，非每战斗）；回放锚 = 录制起点的 world_seed。
- **AI 重算**：AI 决策消费 `ai_decision` 子流 → 重放时同 seed 同 tick 重导出同样决策——**录制面只含玩家输入**（§5 体积控制的关键）。
- **客户端表现流分离**：判定随机与表现随机隔离——客户端拿（判定结果 + 表现 seed 派生）自做暴击字效/粒子/抖动；表现随机漂移无害（不进判定）。
- **实现与禁令**：自写 PCG32 + SplitMix64（数十行，无依赖，统计性质充分）；禁 `rand()`/`mt19937` 全局实例（状态游标不可重放）、禁 Lua `math.random`（沙盒已裁，注入 `apollo.rng(stream, n)`）、禁「时间做种子」。

## 5. 回放格式与验证

**录制物 = 四元组**：

| 件 | 内容 | 来源 |
|---|---|---|
| `binary_id` | 引擎 + 契约版本 hash（schema_hash 族） | 构建/握手已有 |
| `world_seed` | 建服种子 | §4 |
| 起始快照位点 | journal 位点 + tick 号（clock-and-time §7 双写） | attribute-sync §8.2 |
| 输入序列 | 玩家上行 intent 按 (session, seq, tick) 记录 | 会话层 L1 解帧后——与属性 seq 同源；AI 不录（§4 重算） |

**验证 = 事件流 hash 链**：每 tick 末对战斗事件集按规范序（entity_id）序列化，滚动 `h_t = H(h_{t-1} ‖ 事件集_t)`；链头随 tick 推进、内存 ring 保存、定期落盘（崩溃可定位最后一拍）。重放器（apps/ 侧离线工具）从快照位点逐 tick 重模拟、重算链、与线上对照——**分歧 tick 即定位点**（bug 复现二分 / 作弊对账证据）。

**两形态分开**（成本差三个量级）：

- **观战/精彩回放 = 事件流重演**：客户端按序播放已录事件集（不重模拟、不需 binary_id 匹配）——录制事件流即可，cheap。
- **复算回放 = 重模拟 + hash 对照**：反作弊对账、bug 复现、结算争议仲裁——需要同 binary + 四元组，按需触发。

**录制策略**：排位/带奖惩的关键战斗**常开**输入录制；普通战斗采样开（容量批 §5 定采样率）；movement intent 全录（重模拟需要移动轨迹）但高压缩（intent 本身小，<100B/条 net-abstraction 预算口径）。

## 6. Lua 侧确定性纪律（接 scripting-lua）

- **注入替代全局**：rng（§4）/ 时钟（读 tick 参数，clock-and-time §2 口诀「做判定只用 tick」）经 `apollo.*` 模块表；沙盒环境已裁 `os.time`/`os.clock`/`math.random`（scripting-lua §4）——战斗脚本触达即启动期报错。
- **遍历**：结算逻辑禁 `pairs`（哈希序不保证且跨运行漂移）——用数组序/`ipairs`/注入的有序迭代器；§3 全序应用在 Lua 侧同款（收集表 → 按 id 排序 → 应用）。
- **指令预算截断确定性**：截断点 = 指令计数（指令流确定 → 计数确定 → 截断点确定）——scripting-lua §6 的预算执法与重放相容，无需额外机制。
- **热替换边界**：战斗实例存活期间锁定脚本版本（热替换在 tick 边界换表，回放器加载录制时版本指针——scripting-lua §3.2 版本指针持久化即回放的脚本版本锚）。

## 7. 与 36 号决策表的收口

- **#16 战斗独立实例与回放**：实例卸载形态（Matchmaker/Instance Manager 骨架，docs/25 §3.1-3.2 可溯）归 P3+ 玩法批；**其确定性前提 = 本件四约束**——跨机实例同 binary 即同确定域（§1）。36 号该行的 docs/25 悬空引用改指本件（登记簿注记，随下一 36 号批次同步）。
- **#18 帧同步只留缝**：缝的内容具体化 = 「服务器权威的重放确定性」（本件）；**lockstep（客户端参与判定）不进路线图**——跨端浮点一致 + 输入延迟补偿是另一量级问题，MMO 服务器权威模型不需要；「留缝」指若未来做小房间玩法（1v1 竞技场 lockstep 化），输入驱动模型（intent 录制 + tick 重放）可复用，判定迁移成本有界。

## 8. 分期落地

- **P1**：RNG 子流组件（modules/base，随定时器轮同族）+ 编译档浮点锁（CMake preset）+ 结算序纪律进代码评审红线；Lua 沙盒禁令随 scripting-lua 实现批；前置 = C-34 ECS 收敛。
- **P2**：输入录制（会话层，与属性 seq 同源）+ 事件流 hash 链（内存 ring + 定期落盘）+ 观战事件流重演。
- **P3**：离线重放器（apps/ 侧工具，复算对照）+ 复算采样策略接入容量批指标（hash 链分歧率/录制体积）+ 战斗实例卸载（36 号 #16 本体）。
