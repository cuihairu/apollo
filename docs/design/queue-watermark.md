# 受理队列水位与过载前置设计（拍板②决策面）

> 状态：**前置设计稿（2026-10-10）；三拍板点已裁 2026-10-10（ADR-016：水位两级 / 过载回调错误码 / tick 预算锚定）**。定位：cell-single-writer 拍板①已裁 ADR-015（(a) 队列化异步受理）后，拍板②「队列水位与过载语义」的决策面展开——钉水位形态三岔、钉过载响应、钉水位数值口径，不写实现细节。体裁仿 net-abstraction §7/battle-instance-offload/cell-single-writer。权威口径 = net-abstraction §4.2/§5.7（水位/背压母件）+ cell-single-writer §5 拍板②候选倾向（两级水位、不丢旧不静默）。

## 1. 基准与现状（A 级实读 + 母件转述，2026-10-10）

**母件口径（net-abstraction §5.7）**：

- **四级水位**（§4.2 客户端侧）服务「低优先级可丢」的客户端体验权衡；**服务器间不 trim**——内部消息每条的丢弃资格归消息分类声明，RemoteEntityCall 默认不可丢。
- **offer 返回码哲学**：BACK_PRESSURED 时调用方决策（排队上限/降频/断言），框架不代掷。
- **有界排队纪律**：「断连排队」与「背压」是同一机制的两个名字，**都必须有界**——无界排队 = 把背压推迟成内存炸弹。
- per-Link 水位独立（慢进程只拖累自己的 Link）。

**进程内受理面（cell-single-writer §3(a)/§5）**：

- (a) 的代价明列「队列水位面要定义（对齐 §5.6 背压水位口径：拒绝/丢旧/水位告警）」——本件即此面的展开。
- 拍板②候选倾向：水位两级（高水位告警 + 顶格拒收回过载错误包），**不丢旧不静默**。
- 调用面已是 `sendRequestAsync` 回调式（socket.hpp:96-100），workerLoop 单线程（socket.cpp:124）——评估面每请求入队时一次深度读，O(1)。
- 停机时序：G-3 镜像「断流 → 队列 drain → gameThread join」（拍板⑤候选倾向，本件不管 drain，只登记交集）。

**预算锚**：tick 100ms@10Hz（clock-and-time §4 定案）；capacity §2.1 三模型实测锚点同型（帧均值/峰值/Sync 每帧/预算占比，i9-10880H 负载 18-24 噪声期）。

## 2. 目标形态（权威口径）

受理队列的过载语义三件：**可观测**（水位越线告警）+ **拒收**（顶格回过载错误，调用方自己决策——§5.7 offer 哲学的进程内版）+ **不丢旧不静默**（存量队头请求不受水位动作影响，过载一律显式应答）。水位数值锚定 tick 预算而非拍脑袋常量。

## 3. 方案三岔展开（水位形态）

### (a) 两级水位——告警线 + 顶格拒收

- **语义**：深度过告警线 → 告警行（结构化行进日志流，cat=system 级）；深度顶格 → 新入队请求拒绝（回调错误码），存量队头照跑。
- **代价**：水位数值要定（§4 拍板 3）；拒收的调用方处置面依赖既有回调错误语义。
- **与 §5.7 关系**：服务器间不 trim 的进程内版——RemoteEntityCall 默认不可丢，拒收=让调用方重试/降频，队列本身不静默丢旧。

### (b) 四级全量照搬 §4.2

按消息分类四级评估（低优先级可丢/延迟聚合/…）。

- **不取理由**：四级服务客户端体验权衡（优先级分流）；进程内受理面只承载 RPC 意图（cell 写操作/查询），无消费者族分档需求，全量照搬 = 复杂度进受理面，违背单写者收口「收敛面」初衷。且 §5.7 已裁服务器间不 trim。

### (c) 无水位无界队列

- **反证**：无界排队 = 内存炸弹（§5.7 明文），把背压推迟成崩溃——比拒收更坏；G-1 收包入队先例（死亡事件/镜像包/恢复重报）也按有界排队设计。否。

## 4. 过载响应形态（拍板②第二问）

- **(A) 回调错误码（倾向）**：`sendRequestAsync` 回调带类型化错误（overload=queue-full），零新协议——复用 §5.7「类型化原因，不代掷猜测」哲学；调用方在回调里重试/降频/报错，与 BACK_PRESSURED 同型。
- (B) 内部域新消息（overload 错误包进契约 internal 域）：进程内一跳不需要 wire 面；M1 接收端复用受理面时若跨进程才需要，届时随 M1 契约批评估——**留缝不预支**。
- (C) 静默丢/静默拒：**反证**——拍板②候选倾向明文「不静默」；静默让调用方把超时当网络故障排障。

## 5. 诚实对比

| 维度 | (a) 两级 | (b) 四级全量 | (c) 无界 |
|---|---|---|---|
| 可观测（告警） | ✓ | ✓ | ✗ |
| 显式拒收 | ✓ 顶格 | ✓（按分类） | ✗ |
| 不丢旧不静默 | ✓ | ✓ | ✗ |
| 消息分类需求 | 无 | **强制**（无对应消费者族） | — |
| 复杂度进受理面 | 最小 | 高 | 零（假解） |
| 与 §5.7 口径距离 | 最近（服务器间不 trim 同型） | 远（客户端语义误植） | 违纪律（无界=炸弹） |
| M1 接收端复用改动 | 零（水位语义同型） | 重做（分类面废弃） | 重做 |

## 6. 拍板点（已裁 2026-10-10 / ADR-016）

1. **水位形态**：**【已裁：(a) 两级】**（告警线 + 顶格拒收）——(b) 客户端语义误植进程内、(c) 内存炸弹反证（§3/§5）。
2. **过载响应**：**【已裁：(A) 回调错误码】**（零新协议、类型化原因）；(B) 契约新消息留 M1 批评估、(C) 静默反证（§4）。
3. **水位数值口径**：**【已裁：tick 预算锚定】**——队列深度 × 单请求处理时长 ≤ tick 预算（100ms@10Hz）的比例起步，静态顶格先取保守值，benchmark 接入受理面后按 §2.1 三模型实测锚点同型校准。
