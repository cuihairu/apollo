# 性能与容量测试计划

> 目的：明确 Apollo MMO 在各阶段的性能、容量、可靠性验证策略，为 NetCore、AOI、DataProxy 等模块提供可重复的测试方法，确保满足 P99 < 60 ms、5000+ CCU 的指标。

## 1. 目标
1. **早期验证**：在开发阶段持续对关键模块进行性能回归，避免后期出现瓶颈。
2. **系统级压测**：在接近真实环境（Staging）下模拟 5k-10k 并发玩家，测量端到端延迟、吞吐、稳定性。
3. **容量规划**：通过测试结果推导所需服务器资源、扩容策略。
4. **故障演练**：结合压力测试，验证容灾、自愈机制。

## 2. 测试环境与工具

### 2.1 环境
- **Test**：模块级压力测试，配置较小（单机/小集群）。
- **Staging**：与生产结构一致（Gate/Zone/AOI/DataProxy/DB/Redis/Kafka），可自动扩缩。
- **网络条件**：在压测工具中注入不同 RTT/丢包策略，模拟弱网。

### 2.2 工具
- 自研 C++/Go 压测客户端（基于 NetCore 协议）。
- Unity SDK 压测脚本，模拟真实客户端行为。
- Locust/JMeter 作为 HTTP API 压测工具。
- Chaos/故障注入工具（模拟网络抖动、服务故障）。
- 指标收集：Prometheus + Grafana + Jaeger。

## 3. 模块级性能测试

| 模块 | 指标 | 测试内容 |
|------|------|----------|
| NetCore | 吞吐、延迟、CPU、内存 | - io_uring/IOCP 单机连接数<br>- 消息打包/解包耗时<br>- KCP/TCP 比较 |
| AOI Service | Enter/Leave 处理延迟 | - AOI shard 承载玩家数<br>- 空间索引性能 |
| DataProxy | QPS、延迟、队列长度 | - Load/Save 批处理<br>- Redis 缓存命中率<br>- 写队列/落库速率 |
| Battle Service | Tick 时间 | - 大规模技能释放<br>- 状态同步 |
| Transport/NNG | 延迟、队列 | - IPC/TCP 切换性能<br>- 背压控制效果 |

## 4. 场景/玩法压测

### 4.1 基础场景
- 主城/野外：5000+ 玩家移动、聊天、交易。
- 副本：每个 Zone 50-100 玩家，模拟副本入口/结算。
- AOI 边缘案例：大量单位聚集、频繁 Enter/Leave。

### 4.2 战斗场景
- 小规模战斗：100v100，技能与 Buff 频繁触发。
- 大型战场（Battle Service）：500+ 玩家集中释放技能。
- 技能/状态同步延迟、命中判定准确率。

### 4.3 社交与经济
- 公会战、聊天、邮件、交易、市场波动，确保 DataProxy/TLog 承载。

## 5. 压测指标与阈值

| 指标 | 目标 |
|------|------|
| 客户端 RTT | 平均 < 80 ms，P99 < 150 ms |
| 服务器处理延迟（Gate→Zone） | P99 < 60 ms |
| AOI 事件延迟 | 平均 < 30 ms |
| DataProxy 写延迟 | 平均 < 100 ms |
| NetCore CPU 占用 | 单线程 < 60% |
| 内存 | 无泄露，长期压测稳定 |
| TLog Backlog | < 1 分钟 |

## 6. 故障与可靠性测试
- **断线/重连**：模拟网络波动，检查 SDK/NetCore 自动重连。
- **服务宕机**：在压测中随机停止 Gate/Zone/AOI，验证 Orchestrator/Transport 回退机制。
- **数据层故障**: Redis/MySQL/Kafka 故障注入，观察 DataProxy 重试、限流、回滚。
- **DDoS 场景**：模拟大量无效连接，测试防刷与限流策略。

## 7. 流程与自动化
- 每次 CI 构建后触发模块级基准测试（可选）。
- 每周运行一次系统级压测（Staging），输出报告。
- 发布前进行全链路压测 + 故障演练，作为上线准入条件。
- 录制压测脚本/场景，版本化管理，确保可复现。

## 8. 报告与决策
- 指标与结论写入性能报告（CPU/内存/吞吐曲线、瓶颈分析、优化建议）。
- 使用报告指导容量规划（每种服务器规格可支撑多少玩家）。
- 对于不达标项，创建优化任务并纳入迭代。

## 9. Roadmap
1. 完成基础压测工具（客户端模拟器、脚本）。
2. 建立自动化压测环境（Staging 集群 + Pipelines）。
3. 逐步覆盖各模块基准测试（NetCore/AOI/DataProxy/Battle）。
4. 上线系统级压测 + 故障注入。
5. 集成压测结果到部署流程（发布前必须通过）。

---

该计划确保性能目标可衡量、压测任务有章可循，为上线做好准备。***
