# 架构总览

Apollo 面向轻量房间制多人游戏。目标运行链路是 `Client → Gateway → RoomServer → Room`：Gateway 维护客户端连接并路由消息；RoomServer 承载一个或多个房间；Room 是一场对局及其临时状态。Login 负责账号认证和登录凭证，持久化保存跨对局数据。

每个玩家在一场对局中只有一个权威运行对象。跨服时迁移该对象的权威归属，接管成功后更新 Gateway 路由并清理源端对象。传输期间允许状态快照短暂存在于两端，但不得双重处理请求、推进游戏状态或执行权威写入。

该模型不依赖无缝大世界的空间切片、Cell/ghost 投影或跨进程空间漫游。MMO 是可能的产品规模，不是 Apollo 当前的架构类别；本项目定位为轻量多人在线游戏服务器引擎，特别适合塔防、合作玩法、竞技场和副本。

Gateway 可配合多实例和滚动部署提升服务可用性，但自身不提供连接迁移。RoomServer 允许通过停止分配新房间、等待现有房间结束后退出，进行滚动更新；这不等于活动对局跨版本无损迁移，也不保证现存 TCP 连接不断开。

以上是目标模型。仓库中 `base-app`、`cell-app`、`baseappmgr` 等程序是当前原型实现名称，详见[服务器应用现状](../apps/index.md)；不得将这些遗留名称解释为目标拓扑。BigWorld/KBEngine 术语仅在引擎对照资料中用于解释外部实现。
