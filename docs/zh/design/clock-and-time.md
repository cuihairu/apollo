# 时间与时钟模型

使用现有 Time、WorldHost 和 TimerWheel，明确测量时间、模拟顺序和展示时间的边界，不额外定义同义时钟服务。

## 执行摘要

单调钟测耗时与超时，tick 标识模拟顺序，墙钟记录可读时间。跨进程权威顺序使用代次、序号和持久记录，不通过比较两台机器的时钟决定。

## 1. 当前实现

| 部件 | 当前职责 |
|---|---|
| `apollo::base::Time` | 单调时长读数、墙钟与时间格式化辅助 |
| `WorldHost` | 固定步长、可注入单调时间源、有界追赶及 dropped_ticks |
| `WorldTickContext` | tick_index、delta_seconds 和本地单调时刻 |
| `apollo::base::TimerWheel` | 单写者时间轮，调用方注入单调毫秒推进 |

示例程序中的 GameClockService 是装配示例类型，不是已经交付的框架时钟门面。

## 2. 三类时间

| 时间 | 使用范围 | 限制 |
|---|---|---|
| steady | 耗时、超时、退避、预算补给 | 不作为跨机器可比较的时间戳，不参与可复算玩法判定 |
| tick | 输入归属、模拟顺序与回放 | 进程/对局内解释，不能直接比较独立 World 的 tick |
| wall | 日志、审计、展示、报表 | 不用差值测超时，不决定权威先后 |

不得把 steady 的 epoch 值直接交给墙钟格式化当作真实日期。

## 3. 固定步长

WorldHost 库默认 10 Hz；WorldApp 的默认 tickRateMs 为 50，即 20 Hz。两者是不同配置入口的默认值，不是同时生效的两套模拟节拍。

WorldHost 单次推进最多追赶 5 步；超出的积压记为 dropped_ticks，避免无界追赶阻塞其他工作。时间源可由构造参数注入，用于确定性测试。配置与负载验收需注明实际节拍。

## 4. 暂停与边界

明确区分停止推进模拟、暂停接收新玩法和进程停止。暂停期间是否继续心跳、准入、排空和后台完成由应用策略决定，不能只停止 tick 后就宣称服务可用。

脚本提交、输入消费和后台完成在所属逻辑边界执行；不允许用后台完成时间改变已经结束的 tick 判定。

## 5. 客户端时间

客户端时间用于显示、插值和相关体验策略。服务端根据权威输入规则确认执行顺序；客户端自报时刻不构成写权或历史回滚许可。

## 6. 跨 World 顺序

每个 World 独立计时。迁移使用进程代次、玩家权威代次、迁移标识与目录条件提交。超时只是开始对账的依据，不证明目标没有提交，也不自动允许源端恢复写入。

## 7. 日志与持久记录

日志记录 wall 和 tick 等上下文。journal 序号、结算 ID 和权威代次承担恢复/幂等语义，不能由可读时间戳代替。重启后本地 tick 可以重建，但跨重启的业务次序必须有持久依据。

## 8. 定时器

TimerWheel 由所属线程调用 advance(now_ms)，自身不取 OS 时间、不启动线程。默认精度为 10 ms、每层 64 槽、5 层；具体配置按宿主需要确定。

schedule/cancel 与回调遵守单写者纪律。回调可调度或取消其他项，但不能重入 advance。对象销毁时必须取消相关任务或在回调中验证对象代次，避免回调触及已销毁 Instance。

时间轮使用单调毫秒接口，不能写成当前 API 已改为世界 tick 编号。二者需要宿主显式选择和换算，暂停及追赶规则也须分别验证。

## 10. 验收

验证注入时钟、零时刻启动、固定步长、追赶上限、丢拍计数、倒退输入和定时取消。重连、排空和迁移在独立时钟下验证，不以本机时间相近代替协议正确性。
