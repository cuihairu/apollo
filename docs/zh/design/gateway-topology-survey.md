# Gateway 职责与更新边界

角色对照见[BigWorld 与 Apollo](./bigworld-apollo-mapping.md)。gateway 持有客户端 socket，将长期业务发给 Base、模拟输入发给 cell；worldServer 管理执行进程和拓扑，不是默认的逐帧输入中转站。

## Gateway 的职责

验证登录凭证、关联会话、缓存分开的 Base/模拟路由、转发上下行并拒绝旧会话。多个 gateway 可持续接入新玩家；既有 socket 留在原 gateway。loginServer 托管目录，World 发布已提交位置投影，正常业务直达 Base/cell。

## 两种更新方案

| 方案 | 内容 | 必要条件 |
|---|---|---|
| 支持协议更新的进程替换 | 启动新 Base、cell 或 World，转换状态、恢复准备、交接权威与路由后退出旧进程 | 新旧消息解码、状态转换、未升级服务和客户端兼容、幂等提交、失败恢复。 |
| 仅代码更新 | 消息编号、字段与 wire 保持不变；Lua 在所属执行边界更新，C++ 使用进程替换 | 模块私有状态、旧协程、业务副作用、回滚及必要状态交接有明确规则。 |

APOLLO_ROUTE_COMPAT 的握手白名单不等于业务兼容。不兼容旧客户端的协议变化仍需客户端升级或转换策略；数据库结构演进也需单独处理。

## cell 执行进程替换

1. 启动新 cell 并向所属 World 注册，旧执行端停止接收新分配。
2. 旧端在 tick 边界冻结待交接状态，排平或记录在途操作，gateway 有界暂存后续输入。
3. 新端转换并恢复必要模拟状态，但不激活；完整活动包含成员、怪物、目标、时钟、随机和必要脚本状态。
4. World 条件提交分配和实体模拟代次；目标凭提交依据激活，目录投影与 gateway 路由更新，按序恢复输入。
5. 源端清理，全部迁移或按约定排空后退出；强停导致对局终止不能算连续迁移。

长期资料仍在原 Base，经 database 保存。不能只搬玩家或把离场重置后的 Avatar 当成连续恢复。结算使用稳定 ID；结果不明查询记录，不能盲目重放或双端解冻。

## Base 进程替换

旧 Base 暂停待交接玩家的基础业务写入，排平存储操作，导出长期对象、会话与待处理记录。新 Base 准备后条件提交归属与写入代次，刷新 cell/gateway 的 Base 缓存，隔离旧写并清理。原区服和数据库归属不变；存储端须拒绝旧进程迟到写入。

## worldServer 管理进程替换

交接 Space/Cell 拓扑、执行进程注册及代次、容量/排空、在途创建与迁移决定和提交记录。执行端保留或重新确认管理关联；切换期间暂停新的冲突分配，按代次隔离旧管理端，不能让两个管理端同时分配同一空间。已有 cell 是否继续 tick 取决于有效执行租约/权威规则，须定义控制面失联时的期限及恢复策略。

这份管理状态不同于 Base 资料快照和 cell 模拟快照。当前代码未完成此分离，不能用迁移玩家证明管理端升级已实现。

## 更新方式与承诺

| 结果 | 必须验收 |
|---|---|
| 新连接持续接入 | 多入口、就绪与停止旧端新分配。 |
| 免重新登录 | 恢复认证身份、会话、原 Base 与当前模拟位置。 |
| 客户端 TCP 连续 | 原 gateway 持续运行；替换 gateway 需另外实现连接交接，否则排空或重连。 |
| 活动玩法连续 | 完整状态、输入顺序、单权威交接及失败恢复；等待自然结束不能算连续迁移。 |
