## 0. Criteria and Method

- **"Designed" criterion**: an authoritative carrier exists among the nine documents above — a section, a decision, a phased landing; a one-word mention doesn't count.
- **"Gap" criterion**, one of three: (a) negative space — zero hits for the keywords across the repo/all documents; (b) legacy impersonating design — the code exists but its form conflicts with the design goal with no disposal design; (c) placeholder — the design text carries only bracket placeholders (e.g. sdk-contract.md:206 `[encryption P3]`).
- **Sources**: the 2026-09-30 gap-analysis session (full negative-space search + item-by-item verification); the same day's six user questions (logger/kafka, OTel, Prometheus, BI, openssl, http/curl) all merged in — #4 expanded with crypto-library selection, plus two new rows #10 (observability egress)/#11 (HTTP egress); BI was verified as an already-covered egress + boundary declaration (§4.3) and is not a gap row.
- Status vocabulary: OPEN (not designed) / IN-PROGRESS / CLOSED (backfilled after the design lands, with the landing point).

## 2. The True-Blank List (#1–#17)

### #1 Time and Clock Model — **CLOSED** (docs/design/clock-and-time.md, landed 2026-09-30)

- **What was missing**: the three-clock division of labor (steady monotonic clock drives tick / logical tick number / wall clock for ops and persistence timestamps only), the tick number rather than the timestamp as the world-state arbitration order, client time sync only for display and replay alignment (not into arbitration), cross-process clocks mutually distrusted (authority_epoch/route_version exist; the boundary for time values themselves does not).
- **Evidence**: the six design docs have zero hits for "clock/monotonic clock/steady_clock/time sync"; `GameClockService` is a name without substance — apps/game-server/src/main.cpp:20 is really `struct GameClockService { std::string name = "clock"; }`, a pure demo shell (verified by direct read). Deep-dive precedent: both BW/KBE run 10Hz fixed ticks (mmo-mechanism-deep-dive §8), and neither has a written clock design either — **apollo fills this gap ahead of its precedents, not copying them**.
- **Landing point**: docs/design/clock-and-time.md — a three-clock decision table + the three mantras as red lines (measure durations only with steady / arbitrate only with tick / show humans only wall), TickSource as a process-level single source with bounded catch-up (catch_up_max 2 ticks, beyond that skip the tick and record dropped_ticks), three kinds of legal pause points, persistence as (tick, wall_ms) dual writes, timer-wheel deadlines = tick numbers, cross-process comparison only via seq/position/epoch, and a registered code batch to rewrite GameClockService.

### #2 Battle Determinism and Replay Details — **CLOSED** (docs/design/battle-determinism.md, landed 2026-09-30)

- **What was missing**: cross-endpoint float consistency policy (fixed-point/fixed64/limited float with banned cross-end differing ops), container iteration-order determinism (a stable order source for entity/attribute traversal within a tick), random numbers (seed derivation chain / server-authoritative stream / client presentation stream separation), and replay = recording format for seed + ordered input sequence with replay verification.
- **Evidence**: across the six design docs, "determinism/replay/lockstep/random seed" yields only attribute-sync §10.1's tick-determinism section (G-7 scope; does not cover floats/iteration order/seeds); lockstep is zero-hit in negative-space searches across the three repos (deep-dive §18) — no industry precedent to copy for replay, must be self-defined; docs/25 (the battle doc) was deleted in the B-grade cleanup, leaving its float/seed discussions without a carrier.
- **Landing point**: docs/design/battle-determinism.md — **judge the domain first, then set the constraints** (server-authoritative → the determinism problem shrinks to "same binary, same platform replays identically"; consumers = replay recomputation/cross-process offload/AI recomputation, three isomorphic forms); **four constraints**: unique arbitration domain (scene-thread tick boundary, async never arbitrates) / float discipline (IEEE754 + locked compile flags `-ffp-contract=off`/`-fno-fast-math`/no `-march=native`, **no fixed-point**) / iteration order (simulation phase needs no order; settlement phase is total-ordered by target entity_id) / random numbers (`(world_seed, tick, stream_id)` substream-derived PCG32, streams partitioned combat_roll/drop/ai_decision/proc, AI recomputation not recorded); **the replay four-tuple** (binary_id/world_seed/snapshot position/input sequence) + a rolling event-stream hash chain for cross-checks, with spectator = event-stream replay and recomputation = re-simulation kept as two separate forms; on the Lua side, banned in settlement: pairs/os.time/math.random (sandbox pruned + injected); prerequisite = C-34 ECS convergence; closes 36 #16/#18 seams (§7); docs/25's NNG references re-point to InterServerLink per the §15.2 retirement.

### #4 Client Channel Security Semantics + Crypto Library Selection — **CLOSED** (net-abstraction §5.9, landed 2026-09-30)

- **What was missing**: handshake authentication (how certs/tokens are issued, the relationship with login-app), ECDH key agreement + symmetric algorithm choice (AES-GCM/ChaCha20-Poly1305), seq anti-replay, MITM protection/anti-reconnect-hijack; **crypto library selection** (merged from the 2026-09-30 added question).
- **Evidence**: sdk-contract.md:206's frame-layer diagram has the bracket placeholder `[encryption P3]`, no expansion anywhere in design. Crypto library inventory verified: openssl **is already a vcpkg.json direct dependency** (:6, first dependencies entry); websocket.cpp:38 uses `<openssl/sha.h>` (WS handshake); modules/net/CMakeLists.txt:135-160's built-in WebSocket branch does `find_package(OpenSSL REQUIRED)`; contract_hash deliberately has zero crypto-library dependencies (decision #4, minimizing the link graph); libsodium has zero hits repo-wide. **Direction set: OpenSSL as the single crypto source, no second library** — selection argument and usage discipline (algorithm tiering/version pinning/MD5 ban etc.) to be written in a P3 batch.
- **Landing point**: net-abstraction §5.9 — encryption as a FrameFilter-family CryptoFilter (§5.5 slot, post-compression position); threat-model scoping (anti-eavesdrop/anti-replay/anti-hijack/anti-MITM, **non-goal = client reverse engineering** — encryption defends against third parties on the network, not players holding the client); handshake sequence (login_token belongs to login-app / X25519+HKDF-SHA256 / per-frame nonce derived from seq / resume redoes ECDH for forward secrecy); algorithm tiering and ban table (MD5/SHA-1 in new code/RC4/DES/bare ECB/CBC-without-MAC all banned); **OpenSSL as the single crypto source, settled** (EVP interface/CRYPTO_memcmp/RAND_bytes discipline, version pinned to 3.x LTS); WSS fallback in P3 with gateway.
