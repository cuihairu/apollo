## 1. 项目概述

### 1.1 项目目标

基于对现有 MMORPG 服务器架构的分析和提炼，重新设计实现一套现代化的游戏服务器框架，具备以下特性：

- **现代 C++17/20**：使用最新 C++ 标准特性
- **跨平台支持**：Windows/Linux 双平台编译
- **模块化设计**：松耦合、高内聚的模块划分
- **高性能**：IOCP/epoll 异步网络模型
- **易扩展**：插件化架构，支持热更新
- **工程化**：CMake + vcpkg 现代化构建管理

### 2.6 服务器标识与进程间通信

#### 2.5.1 ServerID 设计 (uint64)

采用 64 位无符号整数，4 段式设计，简洁稳定：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    ServerID 位段布局 (64-bit)                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌────────────────┬────────────────┬────────────────┬────────────────┐ │
│  │     区域       │      分组      │      类型      │     实例       │ │
│  │    16-bit      │     16-bit     │     16-bit     │    16-bit      │ │
│  ├────────────────┼────────────────┼────────────────┼────────────────┤ │
│  │     63-48      │     47-32      │     31-16      │     15-0       │ │
│  └────────────────┴────────────────┴────────────────┴────────────────┘ │
│                                                                         │
│  示例: 0x0001_0002_0006_0001  (区域1-分组2-GameServer-实例1)            │
│                                                                         │
│  兼容旧格式: "1-2-6-1" 可双向转换                                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 2.5.2 位段定义

| 位段 | 位置 | 长度 | 范围 | 说明 |
|------|------|------|------|------|
| **Region** | 63-48 | 16 bit | 0-65535 | 区域ID（物理区域/机房）|
| **Group** | 47-32 | 16 bit | 0-65535 | 逻辑分组（服务器组/大区）|
| **Type** | 31-16 | 16 bit | 0-65535 | 服务类型 |
| **Instance** | 15-0 | 16 bit | 0-65535 | 实例编号 |

**设计原则：**
- ServerID 是**逻辑标识**，一旦分配就不应变化
- 进程信息、机器信息是**运行时状态**，存放在注册中心
- 4 段 × 16 位 = 足够覆盖绝大多数场景

#### 2.5.4 ServerID 操作接口

```cpp
// include/apollo/core/server_id.hpp
namespace apollo::core {

class ServerId {
private:
    uint64_t id_ = 0;

public:
    constexpr ServerId() = default;
    constexpr explicit ServerId(uint64_t id) : id_(id) {}

    // 构造器
    static constexpr ServerId Create(uint16_t region, uint16_t group,
                                     uint16_t type, uint16_t instance) {
        return ServerId(
            (static_cast<uint64_t>(region) << 48) |
            (static_cast<uint64_t>(group) << 32) |
            (static_cast<uint64_t>(type) << 16) |
            static_cast<uint64_t>(instance)
        );
    }

    static constexpr ServerId Create(uint16_t region, uint16_t group,
                                     ServerType type, uint16_t instance) {
        return Create(region, group, static_cast<uint16_t>(type), instance);
    }

    // 分量访问
    constexpr uint16_t GetRegion() const { return static_cast<uint16_t>(id_ >> 48); }
    constexpr uint16_t GetGroup() const { return static_cast<uint16_t>(id_ >> 32); }
    constexpr uint16_t GetTypeValue() const { return static_cast<uint16_t>(id_ >> 16); }
    constexpr ServerType GetType() const { return static_cast<ServerType>(GetTypeValue()); }
    constexpr uint16_t GetInstance() const { return static_cast<uint16_t>(id_); }

    // 转换
    constexpr uint64_t ToUint64() const { return id_; }

    // 字符串格式: "1-2-6-1"
    std::string ToString() const {
        return fmt::format("{}-{}-{}-{}",
            GetRegion(), GetGroup(), GetTypeValue(), GetInstance());
    }

    static ServerId FromString(const std::string& str) {
        uint16_t r, g, t, i;
        if (sscanf(str.c_str(), "%hu-%hu-%hu-%hu", &r, &g, &t, &i) == 4) {
            return Create(r, g, t, i);
        }
        return ServerId{};
    }

    // 比较
    constexpr bool operator==(const ServerId& other) const { return id_ == other.id_; }
    constexpr bool operator!=(const ServerId& other) const { return id_ != other.id_; }
    constexpr bool operator<(const ServerId& other) const { return id_ < other.id_; }
    constexpr explicit operator bool() const { return id_ != 0; }

    // 匹配器（用于路由）
    constexpr bool MatchType(ServerType type) const { return GetType() == type; }
    constexpr bool MatchRegion(uint16_t region) const { return GetRegion() == region; }
    constexpr bool MatchGroup(uint16_t group) const { return GetGroup() == group; }
};

// 哈希支持 (用于 unordered_map)
struct ServerIdHash {
    size_t operator()(const ServerId& id) const noexcept {
        return std::hash<uint64_t>{}(id.ToUint64());
    }
};

} // namespace apollo::core
```

#### 2.5.5 注册中心与运行时元数据

ServerID 只是逻辑标识，运行时信息存放在注册中心：

```cpp
// 注册中心存储的服务元数据
struct ServerMeta {
    ServerId id;                    // 逻辑标识 (稳定不变)

    // === 运行时信息 (动态变化) ===
    std::string host;               // 机器IP或主机名
    uint16_t port;                  // TCP监听端口
    std::string unixSocketPath;     // Unix Socket路径 (可选)
    uint32_t pid;                   // 进程ID
    uint64_t startTime;             // 启动时间
    std::string version;            // 版本号

    // === 状态信息 ===
    enum class Status { Starting, Running, Stopping, Offline };
    Status status = Status::Offline;
    uint64_t lastHeartbeat;         // 最后心跳时间
    uint32_t load;                  // 负载值 (用于负载均衡)

    // === 能力标记 ===
    bool supportsUnixSocket = false; // 是否支持 Unix Socket
    bool supportsSharedMemory = false;
};
```

#### 2.5.7 注册中心接口

```cpp
// include/apollo/core/registry.hpp
namespace apollo::core {

class IRegistry {
public:
    virtual ~IRegistry() = default;

    // 注册/注销
    virtual bool Register(const ServerMeta& meta) = 0;
    virtual bool Unregister(const ServerId& id) = 0;

    // 查询
    virtual std::optional<ServerMeta> Get(const ServerId& id) = 0;
    virtual std::vector<ServerMeta> GetByType(ServerType type) = 0;
    virtual std::vector<ServerMeta> GetByRegionGroup(uint16_t region, uint16_t group) = 0;
    virtual std::vector<ServerMeta> GetAll() = 0;

    // 心跳
    virtual bool Heartbeat(const ServerId& id, uint32_t load = 0) = 0;

    // 监听变化
    using ChangeCallback = std::function<void(const ServerId&, const ServerMeta*, bool removed)>;
    virtual void Watch(ChangeCallback callback) = 0;
    virtual void WatchType(ServerType type, ChangeCallback callback) = 0;
};
```

```cpp
namespace apollo::network {

// 异步 I/O 后端类型
enum class ReactorBackend {
    Auto,       // 自动选择最佳后端
    IOCP,       // Windows IOCP
    Epoll,      // Linux epoll
    IoUring,    // Linux io_uring (5.1+)
};

class IReactor {
public:
    virtual ~IReactor() = default;

    virtual bool Start(uint16_t port, int threadCount = 4) = 0;
    virtual void Stop() = 0;
    virtual void Run(int timeout_ms = -1) = 0;

    virtual void SetSessionFactory(SessionFactory factory) = 0;
    virtual void SetPacketParser(std::unique_ptr<IPacketParser> parser) = 0;

    // 获取后端类型
    virtual ReactorBackend GetBackend() const = 0;
};

// 运行时检测并选择最佳后端
inline ReactorBackend DetectBestBackend() {
#ifdef _WIN32
    return ReactorBackend::IOCP;
#else
    // 检测 Linux 内核版本
    struct utsname info;
    if (uname(&info) == 0) {
        int major = 0, minor = 0;
        sscanf(info.release, "%d.%d", &major, &minor);

        // Linux 5.10+ 推荐使用 io_uring
        if (major > 5 || (major == 5 && minor >= 10)) {
            // 额外检查 io_uring 是否可用
            if (io_uring_queue_init_available()) {
                return ReactorBackend::IoUring;
            }
        }
    }
    return ReactorBackend::Epoll;
#endif
}

// 工厂函数
std::unique_ptr<IReactor> CreateReactor(ReactorBackend backend = ReactorBackend::Auto);

// 平台相关类型别名
#ifdef _WIN32
    using PlatformReactor = IOCPReactor;
#else
    // 运行时选择，编译时使用 epoll 作为默认
    using PlatformReactor = EpollReactor;
```

## 7. 开发规范

### 7.1 代码风格

基于 Google C++ Style Guide，部分调整：

```yaml
# .clang-format
BasedOnStyle: Google
IndentWidth: 4
ColumnLimit: 100
AccessModifierOffset: -4
AllowShortFunctionsOnASingleLine: Inline
BreakBeforeBraces: Attach
NamespaceIndentation: None
PointerAlignment: Left
SortIncludes: true
```

### 7.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 类/结构体 | PascalCase | `AttributeContainer` |
| 函数/方法 | PascalCase | `GetAttribute()` |
| 变量 | camelCase | `attributeId` |
| 成员变量 | camelCase + 下划线后缀 | `attributes_` |
| 常量 | kPascalCase | `kMaxConnections` |
| 枚举值 | PascalCase | `Type::Add` |
| 命名空间 | 小写 + 下划线 | `apollo::property` |
| 文件名 | 小写 + 下划线 | `attribute_container.cpp` |

### 7.3 目录/模块规范

- 每个模块独立 CMakeLists.txt
- 头文件放在 `include/apollo/<module>/`
- 源文件放在 `src/<module>/`
- 测试文件放在 `tests/unit/test_<module>.cpp`

## 总结

本设计方案基于对现有 MMORPG 服务器架构的深入分析，提出了一套现代化的游戏服务器框架设计，主要特点包括：

1. **现代 C++ 实践**：使用 C++17/20 特性，如 `std::variant`、`std::optional` 等
2. **模块化架构**：清晰的模块边界，松耦合设计
3. **跨平台支持**：Windows/Linux 双平台，使用 CMake + vcpkg 管理
4. **高性能设计**：IOCP/epoll 异步模型，多级缓存，内存池
5. **工程化管理**：完整的构建、测试、文档体系

框架重点关注三大核心系统：
- **通信架构**：高性能网络、消息路由、数据去重
- **配置系统**：热加载、版本管理、依赖校验
- **属性系统**：灵活容器、智能同步、高效持久化
