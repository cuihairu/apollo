## 0. Overall Strategy

Three main lines (mapping one-to-one onto the three structural facts found by the audit):

1. **Consolidate**: first delete/merge the 5 persistence stacks, the 4~5 Entity/ECS sets, the two AOI implementations, the three logging stacks / three RPC stacks running in dual-tree parallel — without consolidation, every change is duplicated across N sets (audit.md §5, persistence.md §2).
2. **Build the Core**: the model and minimal closed loop of the four first-class objects — PlayerAnchor (long-term ownership) + Avatar (scene incarnation) + Scene (runtime boundary) + Instance (eight-state lifecycle). This is the entire content of task brief §39 acceptance items 1-10 (object-model.md §3 anchor table).
3. **Wire It**: the default build must at least assemble and run the minimal chain "login → placement → enter scene → move → AOI broadcast" — the minimal runnable example of task brief §29, threading through the breakpoints of the three main lines (architecture.md §2.2).

Grading (task brief §38: P0 architecture audit / object ownership / Player/Scene/Instance model / lifecycle → P1 Scene Transfer / PlayerDirectory / AOI / Persistence / Recovery / Reconnect → P2 Battle Runtime / ECS / Social / Guild / Party → P3 Deployment / Performance / Observability / DevEx → P4 Documentation / Examples / Benchmark / Tutorial). This plan has absorbed the phase-one audit (seven-piece set) output; the P0 "architecture audit" item is this very deliverable, and **P0 starts from the object-model rebuild**.
