# Apollo Component Lifecycle Management Design

## 1. Design Philosophy

To achieve a Spring-like management system in C++, we need to solve three core problems:

1.  **Lifecycle Standardization**: Defining standard hooks (`Init`, `Start`, `Stop`) for all components.
2.  **Dependency Resolution**: Ensuring `ConfigLoader` starts before `DatabaseService`, which starts before `GameService`.
3.  **Unified Management**: A central `ApplicationContext` to orchestrate these stages.

## 2. Lifecycle Definition

We define the following standard lifecycle stages for any managed component:

| Stage             | Hook Method           | Description                                 | Typical Usage                             |
| ----------------- | --------------------- | ------------------------------------------- | ----------------------------------------- |
| **0. Construct**  | `Constructor`         | Basic memory allocation. No logic.          | `new Service()`                           |
| **1. Configure**  | `OnConfigure(Config)` | Read static configuration.                  | Read `server.xml`, set ports.             |
| **2. Initialize** | `OnInit()`            | Allocate resources, prepare internal state. | Connect to DB, pre-allocate memory pools. |
| **3. Start**      | `OnStart()`           | Begin active work.                          | Open Listen ports, start threads.         |
| **4. Ready**      | `OnReady()`           | System is fully up.                         | Send "Server Ready" signal to Monitor.    |
| **5. Stop**       | `OnStop()`            | Stop accepting work.                        | Close Listen ports, kick players.         |
| **6. Destroy**    | `OnDestroy()`         | Release resources.                          | Close DB connections, free memory.        |

## 3. Component Types

We categorize components to determine their default priorities:

1.  **Infrastructure (Priority 0)**: Logger, Timer, ThreadPool.
2.  **Configuration (Priority 10)**: ConfigLoader, HotReloadManager.
3.  **Data Access (Priority 20)**: DatabaseConnection, RedisClient.
4.  **Core Services (Priority 30)**: SessionManager, EventDispatcher.
5.  **Business Logic (Priority 40)**: GameService, ChatService, GuildService.
6.  **Gateway/Network (Priority 50)**: TcpServer, WebSocketServer (Must start last, stop first).

## 4. Implementation Design

### 4.1 The Interface (`IComponent`)

```cpp
#include <string>
#include <vector>
#include <future>

class IComponent {
public:
    virtual ~IComponent() = default;

    // Metadata
    virtual std::string GetName() const = 0;
    virtual int GetPriority() const { return 30; } // Default to Core Service

    // Lifecycle Hooks (Return bool or future for async startup)
    virtual bool OnInit() { return true; }
    virtual bool OnStart() { return true; }
    virtual void OnStop() {}
    virtual void OnDestroy() {}

    // Hot Reload Support
    virtual void OnReload() {}
};
```

### 4.2 The Manager (`ApplicationContext`)

This class manages the registration, dependency sorting, and lifecycle execution.

```cpp
class ApplicationContext {
public:
    static ApplicationContext& Instance();

    // Registration with Dependency Declaration
    template<typename T>
    void Register(const std::string& name) {
        auto component = std::make_shared<T>();
        components_.push_back(component);
        nameMap_[name] = component;
    }

    // Start Sequence
    bool Startup() {
        // 1. Sort by Priority (Ascending)
        SortComponents();

        // 2. Init Phase
        for (auto& comp : components_) {
            LOG_INFO("Initializing %s...", comp->GetName().c_str());
            if (!comp->OnInit()) {
                LOG_ERROR("Failed to init %s", comp->GetName().c_str());
                return false;
            }
        }

        // 3. Start Phase
        for (auto& comp : components_) {
            LOG_INFO("Starting %s...", comp->GetName().c_str());
            if (!comp->OnStart()) {
                return false;
            }
        }

        return true;
    }

    // Shutdown Sequence (Reverse Order)
    void Shutdown() {
        // Stop in reverse priority (Network first, then Logic, then DB)
        for (auto it = components_.rbegin(); it != components_.rend(); ++it) {
            LOG_INFO("Stopping %s...", (*it)->GetName().c_str());
            (*it)->OnStop();
        }

        for (auto it = components_.rbegin(); it != components_.rend(); ++it) {
            (*it)->OnDestroy();
        }
    }

private:
    std::vector<std::shared_ptr<IComponent>> components_;
    std::unordered_map<std::string, std::shared_ptr<IComponent>> nameMap_;

    void SortComponents() {
        std::sort(components_.begin(), components_.end(),
            [](const auto& a, const auto& b) {
                return a->GetPriority() < b->GetPriority();
            });
    }
};
```

### 4.3 Usage Example

```cpp
// 1. Infrastructure (Priority 0)
class LoggerComponent : public IComponent {
public:
    std::string GetName() const override { return "Logger"; }
    int GetPriority() const override { return 0; }

    bool OnInit() override {
        // Open log files
        return true;
    }
};

// 2. Database (Priority 20)
class DatabaseComponent : public IComponent {
public:
    std::string GetName() const override { return "Database"; }
    int GetPriority() const override { return 20; }

    bool OnInit() override {
        // Connect to MySQL
        return true;
    }
};

// 3. Network (Priority 50)
class NetworkComponent : public IComponent {
public:
    std::string GetName() const override { return "Network"; }
    int GetPriority() const override { return 50; }

    bool OnStart() override {
        // Listen on Port 8080
        // This happens AFTER Database is Init and Started
        return true;
    }

    void OnStop() override {
        // Stop listening immediately
    }
};

// Main.cpp
int main() {
    auto& app = ApplicationContext::Instance();

    // Order of registration doesn't matter due to Priority sorting
    app.Register<NetworkComponent>("Network");
    app.Register<DatabaseComponent>("Database");
    app.Register<LoggerComponent>("Logger");

    if (app.Startup()) {
        // Main Loop
        while (g_Running) {
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
        }
        app.Shutdown();
    }

    return 0;
}
```

## 5. Advanced Features (Optional)

### 5.1 Explicit Dependencies (DAG)

Instead of just `Priority`, we can implement explicit dependencies:

```cpp
// In ApplicationContext
void Register(Component* c, std::vector<std::string> dependsOn);

// Topological Sort
// Before startup, build a DAG and ensure 'dependsOn' components are started first.
```

### 5.2 Async Startup

For slow components (e.g., loading large configs), `OnInit` can return a `std::future<bool>`. The ApplicationContext can wait for all futures in parallel before moving to the next stage.

### 5.3 Hot Reload Hook

The `OnReload()` hook allows components to refresh their state without restarting.

- `ConfigComponent`: Re-reads XML/JSON files.
- `GameService`: Re-fetches updated configs from ConfigComponent.

### 5.4 Component Discovery (Service Locator)

To support finding all components of a specific type (e.g., "Reload all Configs"), we can add a discovery method using `dynamic_cast`.

```cpp
// In ApplicationContext
template<typename T>
std::vector<std::shared_ptr<T>> GetComponentsOfType() {
    std::vector<std::shared_ptr<T>> result;
    for (auto& comp : components_) {
        // Dynamic cast checks if the component inherits from T
        auto casted = std::dynamic_pointer_cast<T>(comp);
        if (casted) {
            result.push_back(casted);
        }
    }
    return result;
}

// Usage: Reload all configs
void ReloadAllConfigs() {
    auto configs = ApplicationContext::Instance().GetComponentsOfType<IConfigLoader>();
    for (auto& config : configs) {
        config->Reload();
    }
}
```

## 6. Spring-like Features Implementation

To bring the developer experience closer to Spring Boot, we introduce Auto-Registration, Configuration Injection, and Phased Lifecycle control.

### 6.1 Auto-Registration (`@Component`)

Instead of manually calling `app.Register<T>()` in `main.cpp`, we use a macro to register components automatically.

```cpp
// AutoRegistry.h
template<typename T>
struct AutoRegistry {
    AutoRegistry(const std::string& name) {
        ApplicationContext::Instance().Register<T>(name);
    }
};

#define REGISTER_COMPONENT(Type) \
    namespace { static AutoRegistry<Type> reg_##Type(#Type); }
```

**Usage:**

```cpp
// GameService.cpp
class GameService : public IComponent { ... };

// Equivalent to @Component
REGISTER_COMPONENT(GameService);
```

### 6.2 Configuration Injection (`@Value`)

We define a `ConfigProperty<T>` wrapper that automatically binds to the configuration system.

```cpp
// ConfigProperty.h
template<typename T>
class ConfigProperty {
public:
    ConfigProperty(const std::string& key, T defaultValue)
        : key_(key), value_(defaultValue) {}

    // Implicit conversion for easy usage
    operator T() const { return value_; }

    void Bind(IConfigLoader* loader) {
        value_ = loader->Get<T>(key_, value_);
    }

private:
    std::string key_;
    T value_;
};
```

**Usage:**

```cpp
class NetworkComponent : public IComponent {
    // Equivalent to @Value("${server.port:8080}")
    ConfigProperty<int> port_{"server.port", 8080};

    bool OnConfigure(IConfigLoader* config) override {
        port_.Bind(config); // Auto-load value
        return true;
    }
};
```

### 6.3 Advanced Lifecycle Control (`SmartLifecycle`)

We refine the lifecycle control to support "Phases" and "AutoStartup" flags, similar to Spring's `SmartLifecycle`.

```cpp
class IComponent {
public:
    // ... existing methods ...

    // Phase: Determines the start order. Lower values start first.
    // Replaces 'GetPriority' with standard Spring terminology.
    // Infrastructure = -1000, Database = 0, Logic = 1000, Network = 2000
    virtual int GetPhase() const { return 0; }

    // AutoStartup: If false, this component must be started manually.
    virtual bool IsAutoStartup() const { return true; }

    // IsRunning: Check status
    virtual bool IsRunning() const { return isRunning_; }

protected:
    bool isRunning_ = false;
};
```

### 6.4 Application Runner (`SpringApplication.run`)

The `main` function becomes extremely simple, acting only as the bootstrapper.

```cpp
// main.cpp
int main(int argc, char** argv) {
    // 1. Load Bootstrap Config (Command line args, env vars)
    ApplicationContext::Instance().SetArgs(argc, argv);

    // 2. Run (Auto-scan and Start)
    // This will:
    //   - Instantiate all REGISTER_COMPONENT classes
    //   - Sort by GetPhase()
    //   - Execute Init -> Start loop
    ApplicationContext::Instance().Run();

    // 3. Wait for Shutdown Signal (Ctrl+C)
    WaitForSignal();

    // 4. Shutdown
    ApplicationContext::Instance().Shutdown();
    return 0;
}
```

### 6.5 Bean Concepts & Lookup Strategies

To align with Spring terminology:

- **Bean**: Any object managed by `ApplicationContext`. In our C++, this is any class inheriting from `IComponent`.
- **Component**: A specific type of Bean that is auto-detected.

We provide robust lookup methods to find Beans by **Name** or **Type**.

```cpp
class ApplicationContext {
public:
    // 1. Get Bean by Name (e.g., app.GetBean<GameService>("gameService"))
    template<typename T>
    std::shared_ptr<T> GetBean(const std::string& name) {
        auto it = nameMap_.find(name);
        if (it != nameMap_.end()) {
            return std::dynamic_pointer_cast<T>(it->second);
        }
        return nullptr;
    }

    // 2. Get Bean by Type (e.g., app.GetBean<IConfigLoader>())
    // Returns the first matching bean (Primary).
    template<typename T>
    std::shared_ptr<T> GetBean() {
        for (auto& comp : components_) {
            auto casted = std::dynamic_pointer_cast<T>(comp);
            if (casted) return casted;
        }
        return nullptr;
    }

    // 3. Get All Beans by Type (e.g., app.GetBeansOfType<IConfigLoader>())
    template<typename T>
    std::vector<std::shared_ptr<T>> GetBeansOfType() {
        std::vector<std::shared_ptr<T>> result;
        for (auto& comp : components_) {
            auto casted = std::dynamic_pointer_cast<T>(comp);
            if (casted) result.push_back(casted);
        }
        return result;
    }
};
```
